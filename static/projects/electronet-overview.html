ElectroNet

REST API для управления иерархической сетью продаж электроники

Демонстрация работы с self-referencing моделями, кастомными permission-классами DRF и ограничением бизнес-логики на уровне API. Трёхуровневая сеть: Завод → Розничная сеть → ИП.

// Стек

Django 5.2 DRF 3.16 PostgreSQL DRF-spectacular pytest-django JWT Docker / CI/CD

// Модель данных

NetworkNode
 ├── supplier → NetworkNode (self FK)
 ├── address → Address
 └── products → Product
СущностьПоля / особенности
NetworkNodename, email, supplier (FK self), debt (Decimal), level (auto), address
Addresscountry, city, street, house_number
Productname, model, release_date, node (FK)

// Иерархия сети

УровеньТип
0Завод (без поставщика)
1Розничная сеть (поставщик — завод)
2ИП (поставщик — звено уровня 1)

Уровень вычисляется автоматически по положению в иерархии, а не по названию.

// Права и ограничения API

  • Доступ только для авторизованных (is_authenticated=True) + активных (is_active=True) + сотрудников (is_staff=True)
  • Поле задолженноть (debt) — read-only в API (PUT/PATCH запрещены), управление через админку и внутреннюю бизнес-логику
  • Разделены List и Detail сериализаторы для оптимизации ответов

  • Кликабельная ссылка на поставщика
  • Фильтр по городу
  • Admin action для очистки задолженности
  • Просмотр связанных продуктов

// Архитектурные решения

  • Self-relation ForeignKey для гибкой иерархии
  • Уровень (level) вычисляется автоматически, исключает логические ошибки и гарантирует целостность иерархии
  • Управление задолженностью осуществляется через админ-панель или бизнес-логику. Финансовые данные защищены от изменения через публичный интерфейс
  • Контактные данные вынесены в отдельную модель для масштабирования и повторного использования
  • Соблюдается принцип минимальных привилегий: доступ к API ограничен активными сотрудниками
  • Реализована seed_data management command для тестовых данных
