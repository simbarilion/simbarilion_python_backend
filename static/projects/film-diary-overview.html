FilmDiary

Fullstack-платформа персональных рекомендаций фильмов

Кино-трекер без социальной составляющей: пользователь смотрит → оценивает → получает рекомендации → планирует следующий просмотр. Данные полностью изолированы, личные оценки приоритетнее внешних рейтингов.

// Стек

Django 5.2 DRF 3.16 PostgreSQL Celery + Redis TMDB API Telegram Bot API JavaScript / AJAX pytest (79%) Docker / CI/CD

// Архитектурные принципы

  • Разделение доменной логики и API-слоя
  • Сервисный слой для рекомендаций
  • Кэширование внешних запросов к TMDB
  • Идемпотентные Celery-задачи
  • Строгая модель прав доступа (User / Manager / Superuser / Blocked)

// Права доступа

  • Гость — главная, обратная связь
  • Пользователь — каталог, поиск, «мои фильмы», отзывы, календарь; CRUD только своих объектов
  • Manager — просмотр данных пользователей, блокировка аккаунтов, менеджер-панель
  • Superuser — полный доступ
  • Заблокированный — вход запрещён, сессии удаляются, доступна только обратная связь

// TMDB API интеграция

Tmdb() → requests + Django cache (TTL 1–12ч) → TmdbFilm dataclass
 ├── _get() — GET + retry(3) + backoff + MD5 cache_key
 └── _get_multipage() — пагинация

Реализованы поиск фильмов, получение детальной информации, актёрского состава (credits), подбор фильмов по жанрам и формирование пула кандидатов для рекомендательной системы.

Для повышения производительности добавлено кэширование запросов (ключ по URL и параметрам с хешированием алгоритмом MD5), обработка повторных попыток при ошибках 429/5xx (retry), таймаут запросов 5 секунд и локализация данных на русском языке (language=ru-RU).

// Система рекомендаций

Content-based filtering система, включающая три уровня: feature extraction → user profile → similarity scoring.

  • Структурное сходство (70%) — взвешенный Jaccard: director > actor > genre > keyword
  • Текстовое сходство (30%) — TF-IDF косинус по overview и tagline
  • Жанровый бонус — совпадение с топ-жанрами пользователя

Оптимизации: инвертированный индекс, top-K кандидатов, TF-IDF sparse matrix, FeatureCache, логарифмическое затухание старых просмотров, кэш рекомендаций на 24 ч.

// DRF: calendar_events

  • CRUD API /api/calendar_events/ — активные планы и архив
  • ManagerOrOwnerPermission, пагинация 12/стр, upcoming (48 ч)
  • Frontend: AJAX-загрузка, группировка по датам, модальные окна
  • Telegram-напоминания в 12:00–12:30 по локальной TZ пользователя

// Frontend (AJAX + JavaScript)

Vanilla JS без полной перезагрузки страниц: добавление в списки, обновление карточек, динамический календарь через DRF, пагинация, модальные CRUD, поиск. Частичный SPA-подход поверх Django.
