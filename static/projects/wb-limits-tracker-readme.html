WB Limits Tracker

Telegram-бот для отслеживания лимитов приёмки на складах Wildberries

Пользователь регистрируется, вводит API-ключ WB, выбирает склады и получает уведомления, когда появляются бесплатные или дешёвые слоты приёмки. Поддерживаются demo-режим (mock API) и production (webhook + real WB API).

// Архитектурные решения

  • Два режима WB API (WB_API_MODE) — mock (JSON-фикстуры, демо без аккаунта продавца) и real (реальные эндпоинты через httpx)
  • Два режима запуска (USE_POLLING) — long polling для dev/demo и webhook через Flask для production
  • Слой абстракции WbClient — бизнес-логика не зависит от конкретной реализации API
  • FSM — пошаговая настройка: API-ключ → выбор складов через inline-кнопки
  • Шифрование API-ключей — хранение в SQLite как enc: + Fernet, миграция legacy plaintext при старте
  • Разделение sync/async — Flask синхронный, async_runtime прокидывает корутины aiogram в event loop
  • Scheduler — авто-уведомления только для paid=1, выбранных складов и найденных доступных лимитов

// Что интересного в реализации

Один код — два способа доставки — handlers не зависят от polling или webhook
Mock-слой как подсистема — те же JSON-фикстуры для CI, демо и pytest
Валидация до сохранения — ключ проверяется до записи в БД
Шифрование на границе репозитория — handlers работают с открытым ключом, repo шифрует прозрачно
is_available в модели — правило WB (коэфф. 0 или 1 + allow_unload) инкапсулировано в Pydantic
Два UX-канала — /check и reply-кнопка «Проверить лимиты» → одна логика
FSM + приоритет хэндлеров — reply-кнопки до FSM-fallback, чтобы не застревать в сценарии
Scheduler как потребитель — scheduled_check() вызывает check_limits_html() из services
Pydantic на границе API — Warehouse, AcceptanceCoefficient с alias-полями WB JSON
Логирование по модулям — logs/app.db.log, app.scheduler.log и т.д.

// Принципы

  • Separation of Concerns — Telegram UI, бизнес-логика, persistence и внешний API разделены
  • Open/Closed — новый источник данных = ещё одна реализация WbClient
  • Configuration over code — demo/production через env-переменные
  • Testability first — mock-клиент, фикстуры, temp-БД в pytest, CI без секретов

// Возможности бота

  • Регистрация и валидация API-ключа Wildberries
  • Выбор складов через inline-чекбоксы
  • Ручная проверка лимитов (/check) и демо-режим (/demo)
  • Reply-клавиатура и меню команд
  • Автоматические уведомления по расписанию (подписка)
  • Admin-страница со статистикой (webhook-режим)
